## 4 核 8G 能带多少人，为什么核多反而卡

纯原版 1.21、视距压在 10 以内、不开模组，4 核 8G 跑十来个人同时在线是常见配置。一旦上大型整合包，瓶颈立刻从 CPU 转到内存：轻量整合包 8G 起步，几百个模组的整合包得往 16G 走，否则垃圾回收一抖，全服跟着卡一下。

主线程只用一个核，这是 Java 版服务端的结构决定的。玩家跑图、刷怪、红石电路 ticking，全排在一个线程上。CPU 主频高，这个线程处理得快，TPS 就稳；核心多但主频低，主线程该卡还是卡。所以选机器时先看单核跑分，再看核数。

开服脚本里的两个参数值得弄明白：


java -server -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar paper-1.21-50.jar


`-XX:MaxRAMPercentage=95.0` 让 JVM 最多用掉系统可用内存的 95%。机器 8G，堆上限大约 7.6G。这个值在纯开服环境里合适，但如果机器上还跑着面板、备份脚本或者数据库，95% 就偏高了，容易把系统内存挤爆，降到 70% 到 80% 更稳。

`-Xms128M` 是初始堆内存，启动时只占 128M，用多少涨多少。生存服长时间运行，堆会反复扩张收缩，把 `-Xms` 提到和 `-Xmx` 接近（比如 `-Xms4G`）能减少波动，代价是开机就占住这些内存。

用 Forge 的话不能直接敲上面那条命令。先跑一次 installer：


java -Xms128M -XX:MaxRAMPercentage=95.0 -jar forge-1.21-51.0.23-installer.jar -installServer


# -Xmx4G` 改成 `-Xmx7G`，再用 `bash run.sh` 启动。

## 服务端选哪个：Paper、Fabric、Forge、Mohist 的分工

原版服务端（`minecraft_server.1.21`）由官方提供，没有任何修改，插件和模组都不支持。想装东西就得换。

Paper（`paper-1.21-50`）是 Spigot 的高性能分支，兼容大部分 Bukkit 和 Spigot 插件。生存服默认选它，领地、经济、传送、反作弊这些插件生态都在这边。

Fabric 更轻量，更新速度快，适合追最新版本的玩家和模组开发者。想第一时间上 1.21 的新内容，Fabric 通常是最早跟进的。

Forge 是老牌模组加载器和 API，整合包基本都基于它。1.21 的 Forge 要先运行 installer 的 `-installServer` 生成服务端文件，多一步。

Mohist（`mohist-1.20.2-165`）融合了 Forge 和 Bukkit/Spigot，能同时跑模组和插件。问题在于它只更新到 1.20.2。想在 1.21 上同时装模组和插件，现成的 Mohist 没有，只能退回 1.20.2，或者改用 Fabric 加服务端侧模组的组合，插件那部分就没法照搬 Bukkit 生态了。

## 开服当天最容易卡住的三件事

第一次启动会生成 `eula.txt`，里面是 `eula=false`，改成 `true` 才能继续。这一步不做过不去，报错信息也不直观，很多人卡在这。

然后是 `server.properties`。要关正版验证改 `online-mode`，要换端口改 `server-port`，要开白名单改 `white-list`。改完必须重启实例，配置是启动时一次性读进内存的，改文件不重启等于没改。

端口方面，我的世界服务器默认 25565，玩家连的就是这个。如果同时装了 MCSManager 面板，它会占用 23333 和 24444，别和服务端端口撞上。云服务器还要在安全组里放行对应端口，只改配置文件、不放行安全组，外面照样连不进来。

## 关掉正版验证之后，白名单是唯一的门

`online-mode=false` 意味着服务端不再向微软认证服务器核对你有没有正版，任何人填个用户名就能进。这是离线服能拉来朋友的原因，也是它最大的风险。

公网开服必须同时开白名单：`server.properties` 里设 `white-list=true`，再在控制台用 `whitelist add 玩家ID` 逐个放行。少这一步，你的生存服就是对外开放的，谁来都能拆家。

报错能帮你快速定位问题：

- `Invalid session` 或“登录失败：无效的会话”：服务器开着正版验证，离线登录进不去
- `You are not whitelisted`：白名单没加你
- `Outdated client/server`：客户端和服务端版本对不上
- `Connection refused` 或连接超时：地址或端口错了，或者服务器根本没开

还有几个不容易想到的坑。服务器装了正版验证插件，即使 `online-mode=false` 也会被插件拦下；用外置登录（authlib-injector 配合 LittleSkin、Blessing Skin 这类皮肤站）的服，客户端要选“外置登录”而不是“离线模式”，两边账号体系对不上一样进不去；离线用户名和服里已有玩家重名，会被顶号或直接拒绝。

白名单配好、端口放行、朋友能进来了，机器这边也该定下来了。

## 存档别在服务器运行时直接打包

很多教程教你 `tar -czf backup.tar.gz world`，服务器开着的时候这么干，归档有可能是残缺的。归档的同时区块还在写，打包到一半的文件状态不一致，真出事要恢复的时候才发现备份是坏的。

正确的顺序是四条命令：`/save-off` 停止自动存档，`/save-all` 把内存里的内容全部刷到磁盘，然后归档，最后 `/save-on` 恢复自动存档。中间那几秒服务器不写盘，归档出来的才是完整快照。

要在后台给服务端发指令，用命名管道。先 `mkfifo mc.fifo` 建一个管道文件，启动命令改成：


tail -f mc.fifo | java -Xmx2G -jar XXX.jar nogui > log.log


之后往 `mc.fifo` 里写内容就等于在控制台敲命令。备份脚本可以每 5 分钟用 `list` 查一次在线人数，有人在就每 20 分钟左右备一次，保留 10 份，超出按时间删旧的。没人玩的时候不备份，省硬盘也省 IO。

## 几个常被问到的问题

**4 核 8G 到底能带多少人？**
原版生存服十几个人同时在线没问题，人数上限受视距、红石机器数量、刷怪塔效率影响很大。装了大型整合包，先加内存再谈人数。

**手机能进 Java 版生存服吗？**
能，但要在手机上跑 Java 版客户端（比如 PojavLauncher 这类），基岩版和 Java 版是两个生态，不能直连。手机性能有限，进大型模组服容易卡死。浏览器里也有把 Java 版搬进网页的移植方案，服务端要额外挂代理，能玩，不适合当主力。

**别人的离线服为什么玩着玩着就进不去了？**
离线服的运营成本靠服主自己掏或者靠赞助，生命周期普遍比正版服短。找服玩的话，同时备两三个备用地址，别把存档和社交关系押在单一服务器上。

**Mohist 能上 1.21 吗？**
不能，它停在 1.20.2。1.21 想同时要模组和插件，得另找方案。

**改完 `server.properties` 为什么没生效？**
配置在启动时读取一次，改完必须重启实例。
